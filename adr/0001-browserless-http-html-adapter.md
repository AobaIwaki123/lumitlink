# ADR 0001: ブラウザレスHTTP取得とLit.link固有アダプター

## ステータス

採用

## 背景

対象ページはブラウザで表示できるだけでなく、HTTP GETのレスポンスにプロフィールのメタタグとサーバー側レンダリング用データを含んでいる。常時稼働するAPIのためにブラウザを起動すると、メモリ使用量、起動時間、依存コンポーネントが増える。

## 決定

Goの `net/http` とHTMLパーサーでLit.linkの公開HTMLを取得し、Lit.link固有の解析コードを `internal/litlink` アダプターに閉じ込める。APIは読み取り専用とし、取得結果をインメモリキャッシュする。

## 採用理由

- ブラウザやJavaScriptランタイムが不要で、コンテナや自宅サーバーへ配置しやすい。
- 対象ページはSSRでプロフィールデータを返すため、対象用途ではブラウザ実行が不要。
- Goの静的バイナリとして小さなコンテナに配置でき、Kubernetesで運用しやすい。
- `source` に取得時刻、HTTPステータス、レスポンスサイズ、処理時間を含めるため、APIがどのデータを返したか確認できる。

## 捨てたものとリスク

- Lit.linkがSSRデータの形式やHTML構造を変えると解析できなくなる。
- JavaScript実行後にだけ現れる情報は取得できない。
- ブラウザの描画結果と完全に同じ表示情報を再現することは目的にしない。

このリスクは、解析をアダプターへ隔離し、固定HTMLテスト、ライブCanary、取得サイズ上限、タイムアウトで管理する。高頻度アクセスや大量プロフィール取得には、Lit.linkの利用条件と負荷制限を確認してから拡張する。
