# ADR 0002: 相対評価によるイベント名寄せと同率1位アラート

## ステータス

採用予定

## 背景

`lumi-exporter` は `lumitree` など複数APIのイベントを一つのイベントとして扱う可能性がある。同じライブ名が完全一致しない一方、対象範囲では極端に似たライブ名が多数並ぶ想定ではない。そのためタイトル類似度を厳しくしすぎるより、候補集合の中での相対順位を使う方が実データに合う。

ただし、相対順位だけで同一イベントを確定すると、入力の追加や正規化ルール変更によって誤統合する。1位が同点になるケースは判定器の識別力不足を示すため、データを捨てずにコードレビューへ戻す必要がある。

## 決定

候補ごとに次の特徴量を計算し、重み付き総合スコアで順位付けする。

| 特徴量 | 例 | 目的 |
| :--- | :--- | :--- |
| `title_score` | 正規化後のtoken similarity | 表記ゆれを吸収する |
| `date_score` | 同一ローカル日、近接日、別日 | 日付違いの誤統合を抑える |
| `venue_score` | 会場名の類似度 | 同名公演の識別に使う |
| `artist_score` | 出演者集合の重なり | 出演者情報を利用する |

正規化では Unicode NFKC、大小文字、空白、記号、定型的な開催情報をそろえる。候補は `top_score` と `second_score` の相対差で判断する。

- 候補が一つもなければ `unmatched`。
- `top_score` が最低スコア未満なら `unmatched`。
- `top_score` が最低スコア以上で、`top_score - second_score` がマージン以上なら `matched`。
- 1位が同点、または差がマージン未満なら `ambiguous` とし、自動統合しない。
- `ambiguous` ではアラートを上げ、候補、特徴量、総合スコア、入力ソースURL、正規化後文字列を保存する。

最低スコアとマージンは固定の真理値ではなく、実データのレビューで調整する。初期値はタイトルを緩めにしつつ、日付を別日より高く評価し、同率1位を必ず検出できるテストを置く。

## 捨てたものとリスク

外部の大規模なレコードリンケージ基盤や機械学習モデルは採用しない。イベント件数と運用者が少ない段階では、特徴量を説明できる単純な判定器とレビュー可能なアラートの方が保守しやすい。一方、会場・出演者が欠落したデータでは誤判定が残るため、元イベントIDとソースURLは統合後も保持する。
